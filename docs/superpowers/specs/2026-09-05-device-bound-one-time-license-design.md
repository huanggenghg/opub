# opub 一次付费与设备绑定设计

## 背景

`opub` 当前以公开 PyPI 包和 Agent 技能的形式分发。`AGENT.md` 与
`skills/opub-cli/SKILL.md` 是 Agent 可读取的明文说明，不能作为付费控制边界；
真正的授权判断必须由 `opub` CLI 执行。

本设计面向中国大陆个人开发者，以微信和支付宝收款。用户一次支付人民币
9.90 元后，许可证永久绑定首次激活的设备。产品不建设用户账号体系，不支持
换机、解绑或迁移，首次激活后可永久离线使用。

## 目标

- 整个 `opub` 发布能力都需要有效许可证，而不是只限制 Agent 技能入口。
- 用户从创建订单、支付到取得许可证全程自动完成。
- 支持微信与支付宝，服务端固定售价为 990 分。
- 一笔成功订单只签发一个、只绑定一台设备的永久许可证。
- 激活完成后发布不依赖许可证服务器，可永久离线运行。
- 不保存用户名、密码、手机号或邮箱，不建设用户账号体系。
- 未激活时在读取 Cookie、安装依赖或打开浏览器之前停止。

## 非目标

- 不支持订阅、到期、续费或试用期。
- 不支持换机、解绑、许可证迁移或人工重置。
- 不支持优惠码、多设备套餐或家庭共享。
- 不建设用户中心、登录页或管理后台。
- 不在 MVP 中增加代码混淆、二进制编译或反调试。
- 不支持退款或投诉发生后的离线许可证吊销。

## 已确认的产品规则

- 商品标识：`opub-lifetime-v1`。
- 商品名称：`opub 永久设备许可证`。
- 售价：人民币 9.90 元，即 990 分。
- 价格只能由许可证服务端读取，客户端请求不能包含可生效的金额字段。
- 首次成功激活的设备永久占用该订单。
- 换电脑视为新设备，必须重新购买。
- 主板或操作系统提供的稳定设备标识发生变化，也按新设备处理。
- 同一设备重复请求同一已付款订单时返回同一许可证，不重复签发。
- 同一设备丢失本地许可证后可以再次联网取回原许可证，不需要重复购买；该能力
  不能把许可证转移到不同设备。
- 首次激活必须联网，激活后每次发布只做本地验证。

## 方案选择

采用“面包多 Pay + 自建轻量许可证服务 + 本地签名许可证”。

面包多 Pay 面向个人和个体开发者提供微信、支付宝支付 API，并提供支付成功
Webhook 与订单查询接口。许可证服务不直接信任 Webhook，而是把它当作验单
触发信号，再通过服务端签名的订单查询核对支付状态。

参考资料：

- [面包多 Pay 产品说明](https://p.mbd.pub/)
- [Webhook 异步通知](https://doc.mbd.pub/api/webhook-yi-bu-tong-zhi)
- [订单查询](https://doc.mbd.pub/api/ding-dan-cha-xun)
- [微信 H5 支付](https://doc.mbd.pub/api/wei-xin-h5-zhi-fu)
- [支付宝支付](https://doc.mbd.pub/api/zhi-fu-bao-zhi-fu)

未采用以下方案：

- **个人静态收款码自动监听**：个人码没有适合本产品的可信订单创建、签名回调
  和查单闭环，通知监听、OCR 或截图验款都容易漏单和伪造。微信官方的个人
  二维码收款能力也明确仅支持纯个人收付款，不支持商家收款。
- **微信/支付宝官方商户接口直连**：控制力更强，但需要商户号、应用审核和更多
  接入工作，不符合当前个人开发者的最小上线目标。
- **付款后人工发激活码**：实现容易，但无法满足订单、验款和签发自动化。

微信相关边界参考：

- [二维码收款产品介绍](https://pay.wechatpay.cn/doc/v3/merchant/4012154495)
- [Native 支付开发准备](https://pay.wechatpay.cn/doc/v3/merchant/4015614538)

## 总体架构

系统由三部分组成：

1. **公开客户端**：PyPI 中的 `opub` CLI，以及 `AGENT.md` 和 Agent 技能。
2. **许可证服务**：部署在现有公网 HTTPS 服务器上的 FastAPI 服务。
3. **支付渠道**：面包多 Pay 提供微信、支付宝下单、Webhook 和订单查询。

数据流：

```text
opub CLI
  -> 创建绑定设备的激活会话
许可证服务
  -> 创建面包多支付订单
用户
  -> 微信或支付宝付款
面包多 Pay
  -> 支付成功 Webhook
许可证服务
  -> 服务端查单并核对订单
  -> Ed25519 签发设备许可证
opub CLI
  -> 轮询取得许可证
  -> 本地验签后执行发布
```

`AGENT.md` 和 `SKILL.md` 只规定 Agent 的调用流程。即使用户绕过 Agent 直接运行
CLI，统一发布入口仍会执行同一许可证门禁。

## 许可证服务部署

许可证服务是一个独立的 FastAPI 应用，建议放在仓库的 `license_server/` 目录，
但不包含进 `opub` wheel 或 sdist。

MVP 部署配置：

- 现有服务器和域名提供公网 HTTPS。
- Caddy 或现有反向代理终止 TLS。
- FastAPI 单进程运行。
- SQLite 开启 WAL 模式。
- 每日备份 SQLite 文件和许可证签名私钥。
- 支付密钥和许可证私钥只通过服务器环境变量或秘密管理系统注入。

服务器环境变量：

```text
OPUB_PUBLIC_BASE_URL
OPUB_MBD_APP_ID
OPUB_MBD_APP_KEY
OPUB_LICENSE_PRIVATE_KEY
OPUB_LICENSE_PRODUCT_ID=opub-lifetime-v1
OPUB_LICENSE_PRICE_FEN=990
```

客户端只内置许可证服务 URL 和 Ed25519 公钥，不包含支付密钥或签名私钥。
客户端使用 `cryptography` 完成 Ed25519 验签；许可证服务使用同一套规范化和签名
规则，避免两端序列化差异。

## 数据模型

### orders

```text
session_id           TEXT PRIMARY KEY
provider_order_id    TEXT UNIQUE NOT NULL
device_hash          TEXT NOT NULL
product_id           TEXT NOT NULL
amount_fen           INTEGER NOT NULL
status               TEXT NOT NULL
poll_token_hash       TEXT NOT NULL
created_at            TEXT NOT NULL
paid_at               TEXT NULL
provider_charge_id    TEXT NULL
payway                INTEGER NULL
```

`status` 只允许：`pending`、`paid`、`verification_failed`、`expired`。

### licenses

```text
license_id           TEXT PRIMARY KEY
session_id           TEXT UNIQUE NOT NULL
device_hash          TEXT UNIQUE NOT NULL
signed_payload       TEXT NOT NULL
issued_at            TEXT NOT NULL
```

数据库不保存姓名、手机号、邮箱、密码或用户档案。支付渠道自身依法处理的付款人
信息不复制进许可证数据库。

## 服务接口

### `POST /v1/activation-sessions`

请求：

```json
{
  "device_hash": "64 位十六进制 SHA-256",
  "client_nonce": "至少 128 位随机值",
  "client_version": "当前 opub 版本"
}
```

服务端固定选择 `opub-lifetime-v1` 和 990 分：

- 若该设备已有许可证，响应直接返回原签名许可证，不创建订单。
- 若该设备存在未过期的待支付订单，返回原会话并轮换 `poll_token`；旧轮询令牌
  立即失效，避免多个客户端并发控制同一会话。
- 其他情况创建新订单。

待支付响应包含：

```json
{
  "session_id": "随机 ID",
  "poll_token": "只返回一次的随机令牌",
  "checkout_url": "许可证服务生成的 HTTPS 支付页 URL",
  "expires_at": "ISO 8601 时间"
}
```

服务端只保存 `poll_token` 的哈希。

### `GET /v1/activation-sessions/{session_id}`

客户端使用 Bearer `poll_token` 查询。响应状态为：

- `pending`：尚未确认付款。
- `licensed`：返回签名许可证。
- `verification_failed`：支付订单核验失败。
- `expired`：订单已过期。

### `POST /v1/webhooks/mianbaoduo`

处理规则：

1. 解析 `out_trade_no`，但不直接信任通知中的状态、金额或付款渠道。
2. 找到本地订单；未知订单只记录审计信息，不创建许可证。
3. 调用面包多订单查询接口。
4. 核对供应商订单号与本地激活会话的关联、商品描述、金额 990 分及已支付状态。
5. 在数据库事务中把订单改为 `paid` 并创建许可证。
6. 依赖唯一约束保证重复 Webhook 只产生一个许可证。
7. 返回成功响应，避免供应商持续重试。

### `GET /pay/{session_id}`

提供极简响应式支付页：

- 显示商品名和固定价格 9.90 元。
- 提供微信支付和支付宝支付按钮。
- 移动端调用面包多 H5/WAP 支付。
- 桌面端同时显示当前支付页二维码，用户可用手机继续付款。
- 支付返回页只负责用户体验，不能作为许可证签发依据。

## 设备指纹

客户端按平台读取稳定标识：

- macOS：`IOPlatformUUID`。
- Windows：SMBIOS UUID，并辅以 `MachineGuid`。
- Linux：DMI `product_uuid`，不可用时回退到 `/etc/machine-id`。

不使用 MAC 地址、主机名、用户名或磁盘路径，因为它们容易变化或泄露不必要的
个人信息。

原始标识只在本机内存中短暂存在。客户端将以下规范字符串做 SHA-256：

```text
opub-device-v1\n<platform>\n<normalized-stable-identifiers>
```

只有最终 `device_hash` 会发送到许可证服务或写入许可证。无法取得稳定标识时
拒绝创建订单，返回 `LIC-004`，不生成随机指纹。

## 许可证格式与本地验证

许可证保存到 `~/.opub/license.json`，文件权限为 `0600`。待支付会话保存到
`~/.opub/activation.json`，同样使用 `0600`，用于进程中断后恢复轮询。

签名载荷：

```json
{
  "schema_version": 1,
  "key_id": "签名密钥版本",
  "license_id": "随机 ID",
  "product": "opub-lifetime-v1",
  "device_hash": "SHA-256",
  "issued_at": "ISO 8601 时间"
}
```

服务器对规范化 JSON 字节执行 Ed25519 签名。客户端内置按 `key_id` 索引的可信
公钥集合，使以后可以在保留旧公钥的同时轮换签名密钥。客户端每次发布验证：

1. 文件结构和 schema 版本合法。
2. Ed25519 签名有效。
3. 商品标识匹配。
4. 当前设备哈希与许可证一致。

许可证没有到期时间，也不访问服务器。相同设备重复激活时，服务端返回原许可
证；不同设备不能通过原订单取得该许可证。

## CLI 行为

为保持现有参数形式兼容，新增两个互斥选项：

```bash
opub --license-status
opub --activate
```

以下操作无需许可证：

- `opub --help`
- `opub --version`
- `opub --license-status`
- `opub --activate`

视频、图文和所有平台发布都必须经过许可证门禁。门禁位于统一发布入口，早于：

- 运行环境预检和依赖安装；
- Cookie 或账号文件读取；
- 素材解析和浏览器启动；
- 任何上传或发布调用。

`opub --activate` 的行为：

1. 已有有效许可证时直接成功退出。
2. 有未过期待支付会话时恢复轮询，不新建订单。
3. 否则创建设备绑定订单并用默认浏览器打开支付页。
4. 最长轮询 10 分钟。
5. 收到许可证后先在本地验签，再原子写入许可证文件。
6. 超时保留待支付会话，用户可再次执行命令继续。

## Agent 技能行为

`AGENT.md` 和 `skills/opub-cli/SKILL.md` 增加以下契约：

1. 用户要求发布时，Agent 先运行 `opub --license-status`。
2. 已激活时继续收集或使用用户明确提供的发布参数。
3. 未激活时自动运行 `opub --activate`。
4. Agent 只向用户提示已打开激活支付页，不展示设备哈希、轮询令牌或内部日志。
5. 激活成功后继续原发布任务，不要求用户重新提供素材、标题或平台。
6. 激活失败时只报告稳定错误码和可执行建议。

CLI 是最终授权边界。即使 Agent 未执行预检查，发布入口仍会拒绝未授权调用。

## 错误与退出码

新增许可证错误退出码 `13`。稳定错误码：

```text
LIC-001  尚未激活
LIC-002  许可证损坏或签名无效
LIC-003  许可证属于其他设备
LIC-004  无法取得稳定设备标识
LIC-010  订单尚未支付或支付等待超时
LIC-011  激活服务不可用
LIC-012  支付订单验证失败
```

输出继续使用现有稳定格式：

```text
[opub] <错误码>: <描述>。建议: <可执行动作>
```

激活服务不可用只影响新购买和首次激活。已有有效许可证的发布不访问服务器，
不受服务中断影响。

## 安全边界

- Webhook 不具备签发授权，只能触发服务端查单。
- 客户端不能决定商品、价格或已支付状态。
- 许可证私钥和面包多密钥绝不进入 Git、PyPI 包或客户端日志。
- 轮询令牌使用至少 128 位随机熵，只保存哈希，并通过 HTTPS 传输。
- 创建激活会话和轮询接口按 IP 与设备哈希限速；同一设备同时只保留一个有效的
  待支付会话，降低匿名接口被批量滥用的风险。
- 所有订单状态更新和许可证签发保持幂等。
- 服务端日志不记录支付密钥、完整轮询令牌或原始设备标识。

公开 Python 客户端的限制必须对产品方明确：有能力修改源码的用户可以移除本地
许可证门禁。该 MVP 主要阻止普通复制和同一许可证跨设备使用，不提供强 DRM。
若以后需要更强保护，应将关键付费能力迁移到服务端，或把核心逻辑改为签名的
闭源原生模块；这不属于本次范围。

## 测试设计

### 客户端单元测试

- macOS、Windows、Linux 的设备标识规范化和稳定哈希。
- Linux DMI 不可用时回退到 `machine-id`。
- 所有稳定标识缺失时返回 `LIC-004`。
- 原始设备标识不进入网络请求、许可证文件或日志。
- 正确签名、篡改载荷、错误公钥、错误设备分别得到预期结果。
- 许可证和待支付会话以 `0600` 原子写入。
- 有效许可证离线验证成功，不发生网络调用。
- 未授权发布在环境预检、Cookie 读取和浏览器启动之前返回。
- `--help`、`--version`、`--license-status`、`--activate` 不被门禁阻断。
- 现有发布参数行为保持兼容。

### 服务端单元测试

- 创建订单时忽略客户端金额并固定使用 990 分。
- 同一设备的有效待支付会话被复用。
- 同一设备已有许可证时不创建新订单，并返回原许可证。
- 待支付会话被复用时轮换轮询令牌，旧令牌失效。
- 未知 Webhook 不创建订单或许可证。
- Webhook 到达但查单状态未支付时不签发。
- 订单号、商品或金额不匹配时进入 `verification_failed`。
- 正确付款只签发一次许可证。
- 重复和并发 Webhook 保持幂等。
- 已付款订单不能绑定不同设备。
- 相同订单和设备返回相同签名许可证。
- 轮询必须提供正确 Bearer 令牌。

### 集成与发行测试

- 使用支付沙箱或模拟供应商完成下单、Webhook、查单、签发和轮询闭环。
- 在临时数据目录完成一次激活并断网验证发布门禁。
- 构建 wheel 和 sdist，扫描确认不含私钥、支付密钥和服务器 `.env`。
- 安装构建产物后验证 `opub --license-status` 和未授权退出码 13。
- 验证 `AGENT.md` 与 `SKILL.md` 的错误码和调用顺序一致。

## 运维与备份

- SQLite 数据库每日备份，至少保留 30 天。
- Ed25519 私钥保存一份服务器秘密和两份离线备份。
- 支付订单查询失败时保持待确认或标记 `verification_failed`，绝不猜测成功。
- 初期不建设管理后台；通过只读数据库查询和结构化日志排查订单。
- 投诉 Webhook 记录订单状态，但已签发的离线许可证不撤销。
- 面包多 Pay 审核是上线前置条件；若产品未通过审核，停止正式收款并切换到官方
  商户接口方案，不回退到个人静态收款码自动监听。

## 上线顺序

1. 注册并审核面包多 Pay，配置微信 H5、支付宝支付、回调域名和 Webhook。
2. 部署许可证服务，生成 Ed25519 密钥并完成离线备份。
3. 使用支付沙箱或最小金额测试订单闭环。
4. 在 `opub` 客户端加入设备指纹、本地验签和统一门禁。
5. 更新 `AGENT.md` 与 Agent 技能。
6. 完成构建包秘密扫描和安装测试。
7. 先以内部测试设备完成真实 9.90 元支付。
8. 发布新的 PyPI 版本并启用正式商品。

## 验收标准

- 未付费设备不能执行任何平台发布，且不会读取 Cookie 或打开浏览器。
- 用户可从 `opub --activate` 自动进入微信或支付宝付款。
- 真实支付 9.90 元后，同一 CLI 会话自动取得并保存许可证。
- 相同许可证在另一台设备返回 `LIC-003`。
- 已激活设备断网后仍可发布。
- 重复支付通知不会重复签发许可证。
- 客户端、日志、Git 和 PyPI 构建产物中不存在服务端私钥或支付密钥。
- Agent 能在未激活时引导付款，激活后继续原发布任务。
