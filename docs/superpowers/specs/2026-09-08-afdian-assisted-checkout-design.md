# opub 爱发电辅助购买流程设计

## 背景

opub 0.8.0 在未激活时打开爱发电商品页，由爱发电收款并随机发放激活码。
现有文档使用“不需账号”描述整体流程，容易让用户误以为爱发电付款完全不涉及
平台账号。爱发电实际会在购买过程中要求手机号或邮箱验证，并为首次购买者自动
生成平台账号。

本次只优化购买引导，不改变支付渠道、许可证协议、设备绑定规则或激活接口。

## 目标

- 明确 opub 自身不建设用户账号体系。
- 明确用户无需提前注册爱发电；购买时使用自己的手机号或邮箱完成验证即可。
- 由 Agent 或 CLI 引导用户完成购买、复制激活码和设备激活。
- 避免让 Agent 代填或保存手机号、邮箱、验证码、密码等个人凭证。
- 保留当前爱发电商品地址、自动随机发码和 `opub --activate --code` 流程。

## 方案选择

考虑过三种方案：

1. 只修改 README。改动最少，但用户在真正被许可证门禁拦截时看不到说明。
2. 同时修改 CLI、Agent 技能和公开文档。用户在购买当下获得一致提示，且无需新增
   服务。本次采用此方案。
3. 新建 `dachitech.xyz/opub/buy` 中转购买页。以后切换支付供应商更灵活，但需要
   额外页面、部署和维护，不属于本次降低爱发电注册困惑的必要范围。

## 用户流程

1. Agent 在发布前检查许可证；未激活时运行 `opub --activate`。
2. CLI 打开现有爱发电商品页，并说明用户无需提前注册。
3. 用户在爱发电页面使用自己的手机号或邮箱完成验证和付款。首次购买时由爱发电
   自动生成账号。
4. 爱发电付款成功后随机发放一个激活码。
5. 用户把激活码提供给 Agent，Agent 运行 `opub --activate --code <code>`。
6. 激活成功后 Agent 继续原发布任务，不重复询问发布参数。

## 文案与边界

CLI 在成功或尝试打开购买页后，输出一段简短提示，包含：

- 无需提前注册爱发电；
- 使用用户自己的手机号或邮箱完成验证；
- 付款后复制爱发电发放的激活码；
- 不要求用户向 Agent 提供验证码或账号密码。

“不需账号”统一改为“opub 自身不设账号”。涉及爱发电购买时，统一补充“无需
提前注册，付款验证时由爱发电自动生成账号”。

本次不实现：

- 代注册爱发电账号；
- 接收、转发或存储用户验证码；
- 存储爱发电账号或密码；
- 爱发电 OAuth；
- 新的购买中转页或支付渠道。

## 错误处理

- 浏览器打开失败时，继续显示手动购买链接和同样的验证说明。
- 非交互环境下仍返回现有 `LIC-001` 和退出码 13，建议用户付款取得激活码后使用
  `--code` 激活。
- 用户取消输入或没有提供激活码时不改变现有许可证状态。

## 测试

- CLI 测试验证 `--activate` 会打开既有商品 URL，并输出无需提前注册的说明。
- CLI 测试验证提示不会要求用户提供验证码或账号密码。
- 文档契约测试验证 README、CLI 文档、AGENT.md 与技能文档都区分 opub 账号和
  爱发电自动生成账号。
- 保留现有激活、设备绑定和许可证服务测试，确保本次文案改动不改变授权行为。

## 验收标准

- 用户运行 `opub --activate` 时能理解无需预先进入爱发电注册页面。
- 所有公开说明不再声称爱发电购买完全不需要账号。
- Agent 只引导用户本人完成验证，不索取验证码或账号密码。
- 当前商品页、价格、自动发码和许可证兑换逻辑保持不变。
