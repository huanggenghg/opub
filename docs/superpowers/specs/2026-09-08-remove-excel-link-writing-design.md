# 发布链接改由 Agent 汇总设计

## 目标

发布成功后不再创建或更新 Excel 文件。各平台继续抓取公开链接并通过统一发布结果输出，供调用 opub 的 Agent 汇总并反馈给用户。

## 范围

- 删除抖音、小红书、快手 uploader 内的 Excel 写入调用及相关日志。
- 删除视频号、百家号、B站、微博分发函数中的 Excel 写入调用及相关日志。
- 删除 `utils/excel_writer.py`。项目不再提供 Excel 链接记录 API。
- 保留各平台的链接抓取逻辑与 `result_url` 字段。
- 在统一“发布结果”区为成功结果显示链接；没有链接时仍只显示成功状态。
- 更新 opub Agent 使用文档，明确 Agent 从结果汇总读取链接，不依赖 Excel。

## 数据流

1. 平台 uploader 完成发布并尝试抓取公开链接。
2. 抓取成功时，uploader 返回 `success=True` 和 `result_url`；抓取失败仍按既有规则报告发布状态。
3. 分发层原样返回结果，不写文件。
4. reporter 在对应平台的成功行中输出 `result_url`。
5. Agent 从稳定汇总中提取各平台状态、错误码、链接和总体计数，生成最终回复。

## 输出格式

有链接的成功结果：

```text
抖音: ✅ 成功 https://www.douyin.com/video/123
```

没有链接的成功结果：

```text
抖音: ✅ 成功
```

失败格式保持不变。

## 错误处理

- 链接抓取失败不改变发布本身的成功状态，沿用各平台现有语义。
- 移除 Excel 后，不再出现 Excel 创建、保存、依赖缺失或写入失败相关错误与日志。
- reporter 仅在 `result_url` 为非空值时显示链接。

## 测试

- reporter 单元测试覆盖成功且有链接、成功但无链接、失败三种结果。
- 静态契约测试确保生产发布代码不再引用 `excel_writer` 或 `write_video_link`。
- 文档测试确保 Agent 使用说明仍要求汇报结果链接，并明确从发布汇总提取。
- 运行相关 uploader、dispatch、CLI 测试，确认 `result_url` 契约和发布结果未回归。

## 非目标

- 不改变任何平台的链接抓取方式。
- 不改变发布成功/失败判定或退出码。
- 不迁移、删除用户已有的 `.xlsx` 文件。
- 不新增其他持久化链接的文件或数据库。
