# 发布前校验、平台级恢复与自动检查

用户确认继续完成原评估第 5、2、6 项。沿用当前开发分支，保留前一轮成果，不执行真实发布、付费激活、推送或版本发布。

## 发布前校验

对完整输入先校验平台、内容能力、素材文件类型/存在性、定时时间及序号。所有素材的标题在首次登录之前完成解析，避免第二个素材无效时第一个已经发出。定时遵循现有上传器至少提前两小时的规则。图文转视频在转换前校验全部图片与依赖，不静默丢图。新增 --dry-run：验证输入和依赖，输出待执行计划，不登录、不发布、不自动生成文案或转换素材。

## 平台级恢复

普通发布生成唯一 run_id，将已解析参数和素材指纹保存在数据目录的 SQLite 发布记录中。每个素材/平台组合独立保存 pending、running、success、failed 状态，发布前原子认领，成功/失败后持久化；崩溃遗留 running 视为结果不明，不自动重发。普通新命令始终创建新任务，只有 --resume RUN_ID 才复用历史任务，且不能混入新的发布参数。恢复时校验素材指纹，已成功项沿用原结果并标记 reused，尚未执行或确认未发布的失败项可继续；结果不明的项返回 RUN-004，要求先核实平台状态。保存路径与内容参数，不保存 cookie 内容或激活凭据。恢复沿用快照中的账号路径，不重新自动选择其他账号。

JSON 新增 run_id / mode 和每项 reused；文本输出任务编号。恢复不会重新生成文案。断点序号 --start-from 保留为新任务的素材选择方式。

## 自动检查

修复百家号超时单元测试，让测试时钟推进而非真实等待。增加跨 Python 版本 CI，执行全部本地测试、锁文件验证、wheel/sdist 构建和干净环境 CLI 安装检查。CI 不登录或发布内容。
