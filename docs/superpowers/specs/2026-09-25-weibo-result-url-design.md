# 微博视频发布结果链接修复设计

## 背景与根因

微博视频发布成功后，现有流程会进入视频管理页，持续刷新第一条视频卡片；第一条没有“编辑”按钮时视为仍在审核，出现“编辑”按钮后视为审核通过。该业务判断符合微博当前行为，继续保留。

本次真实发布日志显示，第一轮检查没有编辑按钮，第二轮出现编辑按钮，但随后点击第一条卡片却打开了上一条视频的链接。管理页实际请求的 `GET /api/video/list?cursor=0` 同时证明：第一条已是本次视频，正确 `oid` 为 `1034:5347014536265775`；错误结果 `1034:5345980510306307` 属于第二条旧视频。

根因位于审核状态确认后的 DOM 取链步骤：管理页使用虚拟列表，代码再次通过 `.vue-recycle-scroller__item-view` 定位并点击封面，前端导航状态可能与刚刷新的第一条数据不一致。审核判断本身没有选错作品，但点击弹窗返回了旧作品 URL。

## 目标

- 保留“管理页第一条是刚发布视频”的既有流程。
- 保留“第一条出现编辑能力后审核通过”的判断。
- 审核通过后从管理页列表接口的第一条记录读取真实 `oid`，不再点击虚拟列表卡片取 URL。
- 取链异常不能改变已经确认的发布成功状态，也不能触发重复发布。

## 方案

### 管理页数据读取

在已登录的微博管理页上下文中请求相对地址 `/api/video/list?cursor=0`，读取响应中的 `data.videos[0]`。第一条记录包含：

- `oid`：公开播放页使用的完整字符串，例如 `1034:5347014536265775`；
- `editable`：是否已具备编辑能力；
- `publishing`：是否仍处于发布处理中；
- `titles`：标题列表，用于防御性核对和日志诊断。

不得把 `oid` 或 `mid_str` 转成数值，避免长整数精度损失。

### 轮询与返回

发布成功并进入视频管理页后，继续按现有次数和间隔轮询：

1. 每轮读取列表接口第一条记录；
2. 当第一条尚未 `editable` 或仍为 `publishing` 时继续等待；
3. 当第一条已可编辑且存在格式合法的字符串 `oid` 时，返回 `https://weibo.com/tv/show/{oid}`；
4. 标题与本次标题不一致时不返回链接，继续等待，防止管理页或缓存出现异常；
5. 接口失败、字段缺失、候选不一致或轮询超时时，保留发布成功并返回空链接。

不再依赖封面点击、弹窗捕获或弹出页 URL。

## 错误处理

- 发布提交前的异常仍按发布失败处理。
- 已确认发布成功后，管理页导航、列表接口或取链异常均为非致命错误。
- 取链失败只返回“发布成功，但未获取到视频链接”，不得重新点击发布或自动重试投稿。

## 测试与验收

- 回归测试复现：第一条数据属于本次视频且已可编辑，但旧 DOM 点击路径会返回第二条旧链接；新实现必须直接返回第一条 `oid` 对应 URL，且不触发弹窗点击。
- 覆盖审核中、标题不一致、`oid` 缺失、接口异常和审核通过场景。
- 运行微博相关测试和项目全量测试。
- 补丁版本同步后完成构建、远端 CI、PyPI 上传与全新环境安装验证。
- 使用用户明确确认的视频、标题、描述和标签执行一次真实微博发布；最终结果必须能打开本次视频，且页面标题或正文与本次标题一致。
